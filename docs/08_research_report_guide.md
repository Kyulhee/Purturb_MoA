# Guide 08 — Research Report Generation

## 목적
현재 프로젝트의 모든 stage 문서와 산출물을 기반으로, 처음 읽는 사람도 이해할 수 있는 연구 보고서를 생성한다.

## 워크플로우

### 1. 자료 수집
다음 문서를 순서대로 읽는다:

| 순서 | 문서 | 목적 |
|------|------|------|
| 1 | `CLAUDE.md` | 프로젝트 개요 및 현재 단계 |
| 2 | `stages/01_literature_review.md` | 문헌 리뷰 결과 |
| 3 | `stages/02_framing.md` | 프레이밍 및 가설 |
| 4 | `stages/03_planning.md` | 실험 설계 |
| 5 | `stages/04_analysis.md` | 분석 결과 (핵심 지식, 인사이트, 런 이력) |
| 6 | `objects/current/validation_readiness_card.yaml` | 증거 상태 및 허용 클레임 강도 |
| 7 | `objects/current/result_card.yaml` | 주요 지표 (존재하면) |
| 8 | 최근 run 리포트 | `outputs/analysis/run_XX/run_XX_report.md` (가장 높은 번호 2-3개) |

### 2. 보고서 구조 (10개 섹션)

#### Section 1: 풀고자 하는 문제
- 배경 설명 (기술/분야 소개)
- 핵심 문제 정의
- 왜 중요한지 (실질적 영향)

#### Section 2: 기존 접근 방법
- 표준 평가 지표 (표 형태: 지표명, 측정 대상, 장점, 한계)
- 부분적 선행 연구 (표 형태: 출처, 기여, 한계)
- 벤치마크 연구 (표 형태: 연구, 기여, 우리와의 차이)

#### Section 3: 각 방법론의 장단점 비교
- 근본적 차이점 설명 (코드 블록으로 예시)
- 기존 지표의 한계 요약 (표 형태)
- 수렴 증거 (여러 독립 그룹이 같은 문제를 지적한 경우)

#### Section 4: Gap
- 기존 연구가 놗친 것을 번호 부여 (Gap 1, Gap 2...)
- 우리가 선택한 Gap에 ⭐ 표시
- 각 Gap이 왜 중요한지 설명

#### Section 5: 이번 실험의 차별점
- 새로운 프레임워크 설계 (하위 지표별 정의 포함)
- 가설 정의 (표 형태: 가설, 내용, 측정 방법, 타겟)
- 하류 과업 정의 (표 형태: 과업, 정의, 생물학적 의미)

#### Section 6: 실험 결과 요약
- 데이터셋 정보 (표)
- 모델 구성 (표)
- 가설별 결과 (표 + 해석)

#### Section 7: 검증된 핵심 지식
- 번호 부여, 정량적 데이터 필수 포함
- "유의미한 개선" 금지 → "R² 0.30→0.92" 형식

#### Section 8: 남은 과제와 한계
- 해결된 차단요소 (표: ID, 문제, 해결)
- 미해결 과제 (표: ID, 문제, 심각도, 영향)
- 허용 클레임 강도 (표: 가설, 강도, 한정 조건)

#### Section 9: 실험 이력
- Run별 요약 표 (Run, 날짜, 내용, 결과)

#### Section 10: 참고 문헌
- 인용된 논문 목록 (저자, 연도, 제목, 저널)

### 3. 작성 원칙

| 원칙 | 설명 |
|------|------|
| **초심자 배려** | 전문 용어 최초 사용 시 괄호로 간단 설명. 예: "MSE(Mean Squared Error, 평균제곱오차): 예측값과 실제값의 차이를 제곱해 평균낸 것" |
| **정량 데이터 우선** | "유의미한 개선" 대신 "R² 0.30→0.92 (p < 0.001)" |
| **표 적극 활용** | 비교, 결과, 이력은 표로 정리 |
| **한국어 기본** | 보고서 본문은 한국어. 지표명/논문명은 영어 그대로 |
| **검증된 것만** | tool call로 확인된 사실만 서술. 미검증은 `[unverified]` 표기 |
| **객관적·평이 어조** | 아래 상세 원칙 참조 |

### 3.1 객관적·평이 어조 원칙

연구 보고서는 논문에 근접한 객관적 어조를 사용한다. 감정적·평가적 표현을 배제하고, 사실과 데이터로 서술한다.

#### 금지 표현

| 금지 | 이유 | 대체 |
|------|------|------|
| "충격적", "경이적", "혁신적" | 감정적 과장 | 수치로 대체: "R² -0.30→0.92" |
| "완벽히", "100% 확실" | 절대적 단언 | "모든 3개 데이터셋에서", "95% CI [0.12, 0.45]" |
| "놀랍게도", "흥미롭게도" | 주관적 감탄 | 생략 또는 객관적 서술 |
| "심각한", "치명적" (문제 기술 시) | 평가적 | 구체적 영향 서술: "H3 클레임이 선형 모델로만 검증됨" |
| "우수하다", "뛰어나다" | 평가적 | 수치 비교: "Ridge R²=0.643 vs baseline R²=-0.002" |
| "문제없이", "성공적으로" | 모호·평가적 | 구체적 결과: "B=10,000 bootstrap에서 95% CI가 0을 포함하지 않음" |
| "안타깝게도", "다행히" | 감정 표현 | 생략 |
| "명백히", "분명히" | 단언적 | "데이터에서 확인되듯", "τ = -0.200으로 나타났다" |

#### 필수 표현 패턴

| 상황 | 패턴 | 예시 |
|------|------|------|
| 결과 보고 | 지표명 + 수치 + 조건 | "τ(MSE, Dir_deg) = -0.200 (Norman, N=9 모델)" |
| 존재/부재 | 있다/없다 + 수치 | "순위 반전이 있다 (RPE1 τ=0.333)", "통계적 유의성이 없다 (p=0.12)" |
| 비교 | A vs B + 수치 | "Ridge Dir_deg=0.986 vs mean_predictor Dir_deg=0.000" |
| 한계 | 구체적 조건 명시 | "선형 모델(Ridge)로만 검증됨; DL 모델 검증은 미완료" |
| 통계적 강도 | CI 또는 p값 포함 | "95% CI [-0.12, 0.34], 0 포함 → 독립성 확인" |

#### 어조 체크리스트

보고서 작성 후 다음을 확인:

- [ ] 감정적 표현(충격, 놀라움, 실망 등)이 없는가?
- [ ] "우수/뛰어남/혁신" 등 평가 형용사 대신 수치가 있는가?
- [ ] "있다/없다"로 서술 가능한 부분에 과장이 없는가?
- [ ] 모든 수치에 조건(데이터셋, N, 기준)이 명시되었는가?
- [ ] 한계를 회피하지 않고 명시적으로 서술하였는가?
- [ ] 초심자가 이해할 수 있는 용어 설명이 유지되었는가?

### 4. 저장
- 경로: `docs/research_report.md`
- 기존 파일이 있으면 덮어쓰기 (이전 버전은 git history로 복구 가능)
- 완료 후 파일 경로를 사용자에게 알림

- 주요 가설 검증 완료 후 논문 초안 작성 전
- 사용자 요청 시
