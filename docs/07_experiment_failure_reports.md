# 07. 실험 보고서 작성 가이드

## 개요

실험 가설이 실패하거나 방향이 전환될 때, 해당 이력을 구조화된 보고서로 정리하는 프로세스. `stages/`에는 반영하지 않고 `outputs/analysis/experiment_reports/`에 독립 문서로 보관한다.

## 언제 작성하는가

- 가설이 실패하여 연구 방향을 바꿀 때
- 부분 성공/부분 실패로 RQ별 결과가 혼재할 때
- 방향 전환(pivot)의 결정 과정을 기록할 때
- 사용자가 명시적으로 보고서 작성을 요청할 때

## 보고서 번호 규칙

```
{순번}_{키워드}.md          # 영문 버전
{순번}_{키워드}_kr.md       # 한글 버전
```

예: `01_nap_xgboost_baseline.md`, `01_nap_xgboost_baseline_kr.md`

순번은 기존 보고서의 다음 번호를 사용. 기존 보고서가 04까지 있으면 다음은 05부터.

## 보고서 구조

```markdown
# 실험 보고서 {순번}: {제목}

**실행:** run_XX | **날짜:** YYYY-MM-DD | **결과:** 실패 / 부분 실패 / 전환

---

## 가설
무엇을 검증하려 했는가. 명확한 가설 문장과 출처(어떤 단계에서 파생되었는지).

## 실험 설계
데이터, 모델, 하이퍼파라미터, 비교 대상, 평가 지표. 타인이 재현 가능할 정도로.

## 결과
핵심 수치를 테이블로 정리. 통계량(R2, 상관계수, p-value 등) 포함.

## 실패 원인
근본 원인 분석. "왜 사전에 예측하기 어려웠는가"도 포함.

## 얻은 지식
이 실패에서 무엇을 배웠는가. 다음 단계에 어떻게 반영되는가.

## 다음 단계 (선택)
실패를 바탕으로 수정된 접근이나 후속 실험.
```

## 작성 프로세스

1. **사실 수집**: `outputs/analysis/run_XX/`의 결과 파일, 스크립트, 로그에서 핵심 수치 추출
2. **초안 작성**: 영문 버전을 위 구조에 맞춰 작성
3. **한글 버전**: 사용자가 요청하면 동일 내용을 한글로 요약하여 `_kr.md`로 작성
4. **저장**: `outputs/analysis/experiment_reports/`에 저장
5. **stages/ 미반영**: 보고서 내용은 stages/에 반영하지 않음 (stages/는 설계 결정과 근거만 유지)
6. **커밋**: 사용자 요청 시 별도 커밋으로 반영
